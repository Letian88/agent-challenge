# Design

## Context

参赛契约见 proposal.md 与 `specs/competition-b-llm-deploy/spec.md`。题包正文定义了服务接口、能力门、固定轨迹压测与提交 schema；正式负载内容和规模隐藏，公开开发集只能做相对回归。`challenge.json.abstract`、详细正文和 `challenge.json.scoring` 对排名方式的描述不一致，题包也没有正式截止日期。

## Goals / Non-Goals

**Goals:**

- 把可由题包复核的外部合同转成可测试规格。
- 用“静态提交校验 → 接口冒烟 → token/缓存语义 → 公开开发集 → arena 正式自测”的分层门禁降低长时评测成本。
- 对冲突指标并列取证，不把任一版本悄悄写成最终规则。

**Non-Goals:**

- 本变更不选择最终推理引擎，不把参考镜像或示例参数当作冲榜配置。
- 不实现服务、下载大型数据、启动 8 卡服务、构建镜像或提交 attempt。
- 不臆测模型参数规模、结构、隐藏负载或截止时间。

## Decisions

- **详细正文作为无冲突事项的工作合同**：`task.md` 提供完整接口和门禁；摘要/结构化字段出现冲突时则并列记录并请求组织方确认，不自行覆盖。
- **外部合同与参考实现分离**：接口、token 计数、缓存和提交 schema 是必须行为；vLLM 插件、示例参数和参考镜像仅是可替换实现材料。
- **分层验证**：先验证 `/models`、`/chat/completions`、`/generate`、`/flush_cache`，再跑公开开发集，最后才进入 arena 的长时测试；直接提交完整压测会放大 4 小时/档以上的反馈成本。
- **质量与计量真实性优先**：关闭 thinking、压低输出预算、截断历史、删 tools、伪造时间/token/cache 或假清缓存的方案一律淘汰，即使速度更高。
- **一次只改变一个部署变量**：每个候选记录镜像、模型/tokenizer revision、并发档、质量门和延迟/吞吐差异，避免无法归因。

## Risks / Trade-offs

- [评分口径冲突] → 在主办方确认前同时记录 `n_at_slo`、`tpot_mean`、`tpm_decode` 和 `chain_start_p95`，不宣称最终排序。
- [arena 成员或 quota 不可用] → 创建 GPU 服务前用只读命令复核，未通过则保持阻塞。
- [公开开发集与题包 manifest 资源错配] → 区分 `s1-dev-combined-v1` 与 manifest 数据集的用途，确认前不把 smoke fixture 放进正式提交。
- [正式隐藏负载与公开开发集差异] → 公开集仅用于相对 A/B 和协议回归，不承诺预测正式 `N@SLO`。
- [无截止时间] → 最终提交排期保持待确认，不根据单档/全套评测耗时反推赛期。
- [示例配置容量不足] → 示例只用于跑通协议，任何冲榜配置必须由相同负载下的实测决定。
